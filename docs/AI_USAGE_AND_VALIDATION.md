# AI 使用与验证记录

本文档记录“事件浮力图”当前提交中 AI 实际参与的工作、已经执行的开发提示词、尚未执行的后续规划提示词，以及程序和人工验证边界。

除明确标记为“已执行”的阶段外，后续提示词均不属于当前提交已完成功能。

## 一、AI 实际参与内容

### 1. 第一阶段：材料整理与结构化

AI 参与了以下信息整理与文本分析工作：

- 从候选事件中选择三家存在明确关系的中国上市公司；
- 以中国船舶换股吸收合并中国重工作为主事件；
- 整理公告、新闻、研究观点、传闻、市场反应和辅助事件材料；
- 判断材料是否属于同一事件；
- 从每份材料抽取值得单独核验的主张；
- 将主张区分为 `fact`、`opinion`、`inference`、`rumor`；
- 判断新材料相对旧版本是 `supports`、`supplements`、`updates`、`denies`、`corrects` 或 `supersedes`；
- 区分确认状态、执行状态和市场反应状态；
- 分别判断事件对中国船舶、中国重工和中国动力的 `positive`、`negative`、`mixed` 或 `unclear` 影响；
- 为影响判断保存文本依据、不确定因素和来源引用；
- 整理事件发生、披露、获取和分析更新四类时间。

AI 没有生成历史价格、收益率、成交量或成交额。市场数字来自可追溯行情来源和程序公式。

### 2. 第二阶段：页面设计与实现

AI 根据封板 JSON 设计并实现了：

- “事件浮力图”桌面端主视觉；
- 证据/版本 → 事件 → 公司的 SVG 关系；
- 中国市场红涨/利多、绿跌/利空语义；
- `mixed` 红绿双色和 `unclear` 银白中性状态；
- 停牌、复牌、正常交易、终止上市的独立视觉状态；
- 三个历史演化快照；
- 鼠标悬停和键盘聚焦的关系高亮；
- `prefers-reduced-motion` 支持；
- 1440×900 与 1366×768 浏览器检查。

页面没有重新手写业务事实，业务内容从第一阶段 JSON 和分析运行产物进入数据适配层。

### 3. 第三阶段：保存运行分析管线

AI 实现了保存来源快照到视觉结果的 Demo 管线：

```text
acquisition-output
  → deduplication-result
  → clustering-result
  → analysis-request
  → analysis-response
  → validation-result
  → visual-result
```

运行元数据：

| 字段 | 当前值 |
| --- | --- |
| `run_id` | `material-analysis-001` |
| `prompt_version` | `material-analysis-v1` |
| `model_name` | `unknown` |
| Provider | `saved_result` / `SavedAnalysisProvider` |
| 运行状态 | `completed` |
| 第一阶段 AI 校验状态 | `reviewed` |
| 当前结构校验 | `passed` |

模型名称无法从现有运行材料确认，因此保持 `unknown`，没有猜测具体模型。

### 4. 第四至第六阶段：可追溯详情、通知与关系视觉

AI 在第四阶段实现只读事件详情抽屉和来源追溯；第五阶段实现确定性的相邻版本差异与站内通知；第六阶段把五种 `relation_stage` 映射为稳定 SVG 液态关系。三阶段都继续消费已验证产物，没有修改第一阶段封板数据，也没有把用户变成审核员。

### 5. 第七阶段：统一 AI Provider 接口

AI 在现有 Prompt Builder 和验证链路上补齐统一 `AnalysisProvider`：

- `SavedAnalysisProvider` 继续作为默认、离线且无需密钥的演示模式；
- `OnlineAnalysisProvider` 只实现浏览器安全的禁用契约，不调用真实模型；
- 在线 Provider 未配置安全服务端代理时返回 `ONLINE_PROVIDER_REQUIRES_SERVER_PROXY`；
- 在线失败不伪装为成功，回退保存结果必须显式允许并显示回退状态；
- 固定请求增加 `run_id`、公司关系、去重/转载上下文、允许枚举、引用规则和确定性程序职责；
- AI 分析记录页签显示运行模式、Provider、分析时间、三类校验、视觉写入许可和在线 Provider 状态。

接口说明见 `docs/AI_PROVIDER_INTERFACE.md`。本阶段没有接收、保存或调用真实 API Key。

### 4. 已执行的校验

AI 辅助编写测试和检查程序，实际执行包括：

- 结构和 JSON Schema 检查；
- `company_id`、`event_id`、`source_id`、`claim_id`、`basis_claim_ids` 引用检查；
- 枚举检查；
- 时间格式与顺序检查；
- 禁止 AI 输出或修改行情价格字段；
- 禁止 opinion 或 rumor 单独确认事实；
- 禁止把 suspended 直接当成 negative；
- 保持 confirmed、completed 和市场完全定价相互独立；
- 校验失败时阻断 VisualModelBuilder；
- 三个演化快照状态、未来版本隔离、`mixed`/`unclear` 保留、未知发生时间、键盘交互测试；
- 1440×900 与 1366×768 的页面溢出、重叠、裁切和控制台检查。

### 4. AI 可能出现的错误

AI 仍可能：

- 把观点或传闻错误解释为事实；
- 把两个相似但不同的事件合并；
- 漏掉来源之间的冲突或更新关系；
- 为不同公司给出过度确定的影响方向；
- 混淆事件确认、执行完成和市场计价；
- 生成不存在的引用、枚举、时间或行情数字；
- 用披露时间替代未知发生时间；
- 把相关行情变化写成因果关系。

### 5. 程序防线

程序通过以下方式阻止错误进入视觉结果：

- JSON Schema 拒绝缺失或多余字段；
- 引用校验拒绝不存在的 company、event、source、claim 和 basis claim；
- 枚举校验拒绝非法 impact、确认状态、执行状态和版本关系；
- 时间校验拒绝非法格式及分析时间早于披露时间；
- 行情字段守卫拒绝 AI 响应中的价格、收盘价、收益率、成交量和成交额；
- 事实确认守卫拒绝仅由 opinion/rumor 支持的 confirmed 版本；
- 状态守卫拒绝仅因 suspended 推导 negative；
- `completed` 不自动生成“已完全定价”；
- 校验失败时 `applicable_event_count` 变为0，VisualModelBuilder拒绝生成结果；
- 前端适配层只读取 `validation_run_passed: true` 的视觉产物。

### 6. 当前未实现功能

实时抓取、外部采集 Agent、真实在线模型调用、安全服务端代理、API Key 设置、公司详情页、邮件/短信/浏览器推送、后台任务、移动端和公网部署均未实现。第八阶段的独立仓库、公网URL、最终提交包和最终验收仍只是规划，不是已完成功能。

### 7. 合规边界

AI 对利多、利空、混合和暂不明确的判断只用于产品演示，必须结合来源和不确定性阅读。历史行情只作为时间相关观察，不证明事件因果。当前产品不构成证券研究报告、投资顾问意见或投资建议。
